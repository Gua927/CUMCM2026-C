## 第一问：一键求解与版本归档

```bash
make solve-q1
make test
make template-check
```

主时间口径已按用户确认写入 `config/problem.json`：附件时间作为时段起点，次日0:00映射至当日0:00；官方工作簿最后一行填入日循环下一周期的首时段。每次运行均求解另一时间解释并保存对照，不修改原始模板标签。

优化采用 SciPy/HiGHS 的 MILP，依次最小化费用、近等价费用内的吞吐量及购电总变差，并固定整数模式做高精度连续求解。LP松弛及对偶乘子提供独立费用下界。不能把该确定性结果直接当作后续未知未来问题的可执行成绩。

每次运行在 `output/runs/problem1/<运行版本>/` 新建完整归档，保存输入映射、源码快照、配置、版本与哈希、144时段轨迹、费用和校验、基线、18个敏感性试验及图表。`latest.json`指向最近一次完成的版本。失败运行保留诊断且不发布新结果；旧的已发布工作簿保存在下一次成功运行目录中。

最新成果入口为 `output/results/result1.xlsx`、`output/problem1-report.md`、`output/problem1-dashboard.html`，论文图表位于 `output/figures/q1_*` 和 `output/tables/q1_*`。HTML可离线打开，通过鼠标或滑块查看每个时段；PNG用于预览，PDF用于论文。

敏感性中的容量、功率、效率及光伏缩放均为重新优化的确定性比较，不代表既定计划应对预测误差的表现。运行环境警告原样保存在manifest，测试覆盖可手算的套利、效率和容量案例及故意破坏结果后的审计。

接口参考：[SciPy milp](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html)、[SciPy linprog](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linprog.html)。实际环境版本以每个运行目录的manifest为准。

## 第二问：固定合同与因果风险调度

```bash
make solve-q2
make check-q2
make test
make paper
```

`models/forecasting.py` 从同一过去历史直接预测1—3个目标日，按对应提前期仅使用已成熟残差。`models/problem2.py` 复用第一问物理约定，主模型优化48小时、远端取零残值，仅提交前144时段合同；后半段为条件性辅助规划。控制器包括贪心缓冲、参考SOC跟踪及每小时固定合同滚动控制。`problem2_workflow.py` 在一月比较36组“预测器×分位数×控制器”（季节滞后、趋势、逐时段岭回归三种预测器），记录容差内并列，不再校准旧κ网格。主方案是近似风险策略，不宣称完整随机控制全局最优。

每次保存 `output/runs/problem2/<版本>/`：五种完整策略、逐日费用、决策历史边界、48小时预测和参考轨迹 `issued_plans.csv`、指定日期、64组局部敏感性、物理与求解证书、官方Excel、图表、离线HTML、源码快照和指纹。`boundary/` 保存同参24小时、A替代成本、72小时、48小时固定远端残值及旧版冻结策略。`problem2_export.py` 沿用原模板样式展开省略号并回读，`problem2_reporting.py` 自动生成论文数字。年末不缩短视窗，也不读取次年实测。

统一时间解释是用户确认的每日行末午夜循环映射，SOC仍在规范化日期之间连续。1月实际电池空闲于6000 kWh，仅作预测预热和影子验证；正式评价334天，不将其称为完整365天费用。环境仍有SciPy导入警告，自动数值验证必须通过。初步开发看过全年控制器表现，最终参数由一月排序决定，不能称二月至十二月为未接触独立测试集。

固定结构：目标星期周滞后7天、负荷窗口28天、光伏窗口14天与0.75趋势收缩、三点平滑、各提前期成熟残差56天；回归预测器为直接多步的逐时段岭回归（负荷特征：滞后7天同时段、最近完成日同时段及其日均值；光伏特征：最近完成日同时段及7日均值），每个起报日用最近56个完成日重估系数，样本不足12日退回趋势预测；控制器更新6时段、历史偏差窗口6时段、指数衰减尺度12时段。主视窗48小时，远端零成本的截断效应用72小时和固定残值对照验证；统一比较残值保持最低电价除以充电效率，不使用各策略自己的规划系数给自身记账。具体公式与参数集中记录；复用校准必须同时匹配配置和模型源码哈希。

## 因果性审计（2026-09-12）

运行 `make audit-causality`（`AUDIT_ARGS="--every 7"` 可抽样）。脚本 `scripts/audit_causality.py` 对已发布的
问题二、三、四归档逐日检验：把决策时不可得的数据（附件2当日及之后、附件3当日0:00之后的发布、附件4当日及之后）
全部替换为随机数，重新构造预测、残差库和价格模型，从归档的当日初始电量重发0:00计划并与归档逐时比较，
同时核对规划目标等于视窗内计划购电费减终端项，不含任何紧急购电项。
结果写入 `output/runs/causality/<版本>/` 与 `output/causality-audit.md`，不改动归档和官方工作簿。
首次运行 334 天全部通过，计划最大偏差 4e-12 kWh；毒化后执行轨迹每天都变，说明只有执行读取当天实测。
该审计证明已发布计划只依赖历史数据，不证明模型结构与超参数的开发过程未接触全年（论文按实披露）。

## 职责划分

### 时间口径对照（2026-09-12）

运行 `make compare-time`，固定当前第二问一月选定的预测器、分位数、控制器和规划视窗，
比较 `daily_cyclic_start` 与 `chronological_start` 的二月至十二月连续回放。
独立轨迹、逐日费用、指定日结果、物理校验和输入/源码哈希写入
`output/runs/time_alignment/<版本>/`；不重选参数、不导出官方工作簿、不更新正式版本指针。
脚本还要求日循环回放复现当前已归档主策略，否则报错。

`data.align_daily_samples` 统一处理附件2负荷/光伏与附件4电价的跨日映射；
第四问现在读取与负荷相同的时间配置，避免切换负荷时价格仍静默沿用旧映射。
连续起点解释使用前一行 `0:00+1` 作为当天午夜；首日缺少午夜样本，以首个00:10值补齐，
只用于一月预热；假定观测无额外到达延迟。测试从原始行列开始扰动未来数据，检查过去不受影响。

这仍是两种时标解释的敏感性试验，不是连续时间解释的完整发布流程。
正式默认保留此前日循环口径。**不要只修改配置就发布新结果**：官方模板最后一列标作
次日 `0:00–0:10`，现有导出/回读按当日循环取值；改为连续日历需另行统一计划发布日、
交付日、午夜边界值、年末辅助段与日汇总的关系，再重跑相关问题及论文。
本轮结果与后续优先级见 [时间映射复核](../output/time-alignment-review.md)。

- `config/problem.json`：题面明确给出的储能、时间步长和价格倍率参数；
- `src/cumcm_c/paths.py`：全仓库路径的唯一来源；
- `src/cumcm_c/data.py`：附件 1-4 的读取与基本结构校验；
- `src/cumcm_c/export.py`：复制官方结果模板，后续在此实现安全写回；
- `src/cumcm_c/models/`：按问题 1、2、3、4 拆分确定性优化、随机/鲁棒计划、滚动调整和波动电价模型；
- `scripts/`：只放可直接运行的入口，不在脚本中堆放核心算法；
- `vis/style.py`：论文图片的统一 Matplotlib 样式。

建议模型模块按统一接口返回“10 分钟粒度的计划购电、调整购电、充放电、SOC、紧急购电与费用分解”，再由 `export.py` 写入官方模板。禁止直接覆盖 `doc/Problem/C题/附件/附件5/` 中的原始文件。
